### 항목 20 : '값에 의한 전달'보다는 '상수객체 참조자에 의한 전달' 방식을 택하는 편이 대게 낫다

- 값에 의한 전달은 '사본'을 통해 초기화되며 사본을 돌려받는다

- 사본을 만들어내는 것은 복사생성자이다. 그렇기 때문에 '값에 의한 전달'이 고비용의 연산이 되기도 한다.

- 이러한 비용을 막기 위해서 상수객체에 대한 참조자(reference-to-const)로 전달하게 만드는 것이다.
  
  

- 값에 의한 전달이 사본이기 때문에 원본에는 변화가 없어서 const로 어떤 변화가 생기더라도 그 변화로부터 안전하게 보호를 받아준다.

- 참조에 의한 전달 방식으로 매개변수를 넘기면 복사손실 문제(slicing problem)가 없어지는 장점이 있다
  
  

- 파생 클래스 객체가 기본 클래스 객체로서 전달되는 경우는, 이 객체가 값으로 전달되면 기본 클래스의 복사 생성자가 호출되고 파생 클래스 객체로 동작하게 해주는 특정들이 잘라버린다.

```
class Window{
public: ... 
    std::string name() const; // 윈도우의 이름을 반환한다 
    virtual void display() const; // 윈도우 테두리 및 내부를 그린다.
};

class WindowWithScrollBase: public Window
{
public: 
    ... 
    virtual void display() const;
};

void printNameAndDisplay (Window w)
{ 
    std::cout << w.name(); 
    w.display();
}
WindowWithScrollBars wwsb;
printNameAndDisplay(wwwsb);
```

- wwsb가 WindowWithScrollBars 객체의 구실을 할 수 있는 부속 정보가 전부 없어진다.

- 그래서 파생 클래스로 넘어가도 매개변수가 부모 클래스이니 Window 생성자로 만들어지고 Window::display를 호출하게 된다.

- 복사손실 문제에서 도망가려면, w를 상수객체에 대한 참조자로 전달하도록 만들면 된다
  
  

- 반복자와 함수 객체를 구현할 때는 1. 복사 효율을 높일 것과 2. 복사손실 문제에 노출되지 않도록 만드는 것이 필수이다.

- 진짜 double은 레지스터에 넣어 주지만, double하나로만 만들어진 (사용자 정의 타입) 객체는 레지스터에 넣지 않는 것이다

- 참조에 의한 전달을 쓰는 편이 좋다. 포인터만큼은 레지스터에 확실히 들어가기 때문이다.

- '값에 의한 전달'이 저비용이라고 가정해도 괜찮은 유일한 타입은 기본제공 타입 STl, 반복자, 함수 객체 타입이다.
  
  

### 항목 21 : 함수에서 객체를 반환해야 할 경우에 참조자를 반환하려고 들지 말자

- 함수 수준에서 새로운 객체를 만드는 방법은 스택에 만드는 것, 힙에 만드는 것이다

- 스택에 객체를 만들려면 함수 내부에서 지역 변수를 정의하면 된다. 근데 그 객체에 대한 참조자를 반환하는데, 함수가 끝나면 소멸된다. 

- 함수 내부에서 new로 객체를 만들고 그 참조를 반환하면, 객체 자체는 함수 종료 후에도 살아 있지만 누가 언제 delete해야 하는지 소유권이 불명확해진다.
  
  

- 정적 객체로 구하게 되어버리면 아래와 같은 문제가 발생해버린다

```
const Rational& operator*(const Rational& lhs, const Rational& rhs)
{ 
    static Rational result; 
    result=...; 
    return result;
}

bool operator==(const Rational& lhs, const Rational& rhs);
Rational a,b,c,d;...
if((a*b)==(c*d)){ 
    ...
}
else{ 
    ...
}
```

- 이 if문에서는 항상 true가 된다.

```
if(operator==(operator*(a,b), operator*(c,d)))
```

- 위와 같은 if문이 되는데 각각의 호출을 통해 operator* 안에 정의된 정적 Rational 객체의 참조자가 반환되어 true만 반환된다.

- 그렇다고 정적 배열을 쓰이기에는 이 배열의 사이즈가 부족할 수도 있고 낭비일수도 있기 때문에 해결이 되지 않는다
  
  

- 아래와 같은 코드는 생성 비용은 들지만 operator*의 반환 값에 대한 생성과 소멸 동작이 안전하게 제거될 수 있는 것이다.

```
inline const Rational operator*(const Rational& lhs, const Rational& rhs)
{ 
    return Rational(lhs.n * rhs.n, lhs.d * rhs.d);
}
```
