- @return ITransactionObjectAnnotation 공유 포인터를 반환한다.
- With Editor 버전이다. (`#if WITH_EDITOR`)

`enum class ETransactionAnnotationCreationMode : uint8 { DefaultInstance, FindOrCreate };`

- 트랜잭션 어노테이션의 생성 모드를 나타내는 열거형이다. 기반 타입은 uint8이다.
- DefaultInstance와 FindOrCreate 두 값이 선언되어 있으며, 아래 FactoryTransactionAnnotation의 인자로 사용된다.
- protected 영역에 선언되어 있다. With Editor 버전이다. (`#if WITH_EDITOR`)

`virtual TSharedPtr<ITransactionObjectAnnotation> FactoryTransactionAnnotation(const ETransactionAnnotationCreationMode InCreationMode) const { return nullptr; }`

- 새로운 어노테이션 객체를 생성하고, 필요하면 데이터를 채우는 팩토리 함수이다.
- @param InCreationMode 어노테이션 생성 모드이다.
- 기본 구현은 nullptr을 반환한다.
- protected 함수이다. With Editor 버전이다. (`#if WITH_EDITOR`)

`COREUOBJECT_API virtual bool IsSelectedInEditor() const;`

- UObject가 에디터에서 선택된 상태인지 확인한다.
- @return 선택되어 있으면 true, 선택되어 있지 않으면 false를 반환한다.
- 제공된 코드에서는 protected 영역에 있다. With Editor 버전이다. (`#if WITH_EDITOR`)

`COREUOBJECT_API virtual void PostRename(UObject* OldOuter, const FName OldName);`

- Rename()의 끝에서 호출되며, 이름 변경이 실제로 수행된 경우에만 호출된다.
- @param OldOuter 변경 전 Outer이다. @param OldName 변경 전 이름이다.
- 이 함수부터는 다시 public 영역이다.

`virtual void PreDuplicate(FObjectDuplicationParameters& DupParams) {}`

- 오브젝트 복제 전에 호출된다.
- @param DupParams 복제에 사용될 전체 매개변수이다. 복제 설정을 수정할 수 있다.
- 예를 들어 StaticDuplicateObject가 사용하는 복제 원본 → 복제 대상 매핑을 미리 채우도록 duplication seed를 수정할 수 있다.
- 기본 구현은 아무 작업도 하지 않는다.

`virtual void PostDuplicate(bool bDuplicateForPIE) {}`

- 복제 및 직렬화가 끝난 뒤, PostLoad 전에 호출된다. 예를 들어 UStaticMesh의 UModel도 함께 복제되도록 처리하는 데 쓰인다.
- @param bDuplicateForPIE PIE(Play In Editor)를 위한 복제인지 나타낸다.
- 액터를 Alt+드래그 또는 복사·붙여넣기로 복제할 때 컴포넌트에는 호출되지 않는다. 이 경우까지 처리하려면 PostEditImport도 사용해야 한다.
- 기본 구현은 아무 작업도 하지 않는다.

`virtual void PostDuplicate(EDuplicateMode::Type DuplicateMode) { PostDuplicate(DuplicateMode == EDuplicateMode::PIE); }`

- 복제 모드를 받는 PostDuplicate 오버로드이다.
- @param DuplicateMode 복제 모드이다.
- 기본 구현은 DuplicateMode가 PIE인지 비교한 결과를 bool 버전 PostDuplicate에 전달한다.

`COREUOBJECT_API virtual void PostMigrate(const struct FUObjectMigrationContext& MigrationContext);`

- 오브젝트가 다른 프로세스로 마이그레이션되기 직전과 마이그레이션된 후에 호출된다.
- @param MigrationContext 마이그레이션 컨텍스트이다.
- 원격 오브젝트 핸들 기능 조건에서 제공된다. (`#if UE_WITH_REMOTE_OBJECT_HANDLE`)

`virtual bool IsMigrationRoot() const { return false; }`

- 함수 이름상 오브젝트가 마이그레이션 루트인지 확인하는 함수이다. 제공된 코드에는 별도의 설명 주석이 없다.
- 기본 구현은 false를 반환한다.
- 원격 오브젝트 핸들 기능 조건에서 제공된다. (`#if UE_WITH_REMOTE_OBJECT_HANDLE`)

`COREUOBJECT_API virtual bool NeedsLoadForClient() const;`

- 저장 중 오브젝트와 함께 저장할 로드 플래그를 결정하기 위해 호출된다.
- @return 클라이언트에서 로드해야 하면 true를 반환한다. false이면 이 오브젝트는 클라이언트에서 제외된다.

`COREUOBJECT_API virtual bool NeedsLoadForServer() const;`

- 저장 중 오브젝트와 함께 저장할 로드 플래그를 결정하기 위해 호출된다.
- @return 서버에서 로드해야 하면 true를 반환한다. false이면 이 오브젝트는 서버에서 제외된다.

`COREUOBJECT_API virtual bool NeedsLoadForTargetPlatform(const class ITargetPlatform* TargetPlatform) const;`

- 저장 중 대상 플랫폼에서 이 오브젝트를 로드해야 하는지 결정한다.
- @param TargetPlatform 검사할 대상 플랫폼이다.
- @return 대상 플랫폼에서 로드해야 하면 true를 반환한다. false이면 해당 플랫폼에서 제외된다.

`virtual bool NeedsLoadForEditorGame() const { return false; }`

- 저장 중, 일반적인 클라이언트·서버 로드 조건에서는 제외되는 오브젝트라도 에디터 빌드에서 실행되는 게임의 클라이언트·서버에 포함할지 결정한다.
- @return 에디터 빌드에서 실행되는 게임에 항상 로드해야 하면 true를 반환한다.
- false여도 NeedsLoadForServer 또는 NeedsLoadForClient가 true이면 로드된다. 기본 구현은 false이다.

`virtual bool IsEditorOnly() const { return false; }`

- 저장 중 이 오브젝트를 에디터 전용으로 강제할지 결정한다.
- @return 에디터 밖에서 절대로 로드하면 안 되는 오브젝트이면 true를 반환한다.
- 기본 구현은 false이다. 함수 자체는 이 코드에서 WITH_EDITOR 조건문 밖에 선언되어 있다.

`virtual bool HasNonEditorOnlyReferences() const { return false; }`

- 오브젝트 자체가 에디터 전용이더라도, 그 오브젝트가 참조하는 대상이 게임에서 사용되는지 저장 중에 판단한다.
- 예를 들어 쿠킹 중 이 오브젝트의 참조를 따라가며 처리하는 경우에 해당할 수 있다.
- @return 오브젝트가 에디터 전용이어도 그 참조를 게임에서 사용되는 것으로 표시해야 하면 true를 반환한다.
- 기본 구현은 false이다.



#### 나의 생각

단순한 구현일거 같은 것도 따로 함수로도 두고 에디터 전용, 트랜잭션 등 상황을 고려하여 만들어놓은 함수들이 많은거 같다. 내가 코드 짤 때도 이를 유의하며 짜야겠다고 생각했다.
