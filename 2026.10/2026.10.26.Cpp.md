### 항목 24 : 타입 변환이 모든 매개변수에 대해 적용되어야 한다면 비멤버 함수를 선언하자

```
class Rational{
public:
	...
    const Rational operator*(const Rational& rhs) const;
};

Rational oneEnglish(1,8);
Rational oneHalf(1,2);

Rational result=oneHalf*oneEnglish; // O
result=oneEnglish*oneHalf; // O

result=oneHalf*2; // O
(result=oneHalf.operator*(2))

result=2*oneHalf; // 에러!
(result=2.operator*(oneHalf)
```

맨 마지막 줄은 멤버함수에도 없고 비멤버 버전의 operator*도 없어서 컴파일 에러가 난다. 첫 번째 줄에서 가능한 이유는 암시적 타입 변환과 명시적호출(explicit) 생성자가 없기 때문에 아래와 같이 실행한다.

```
const Rational temp(2); // 2로부터 임시 Rational 객체를 생성한다.
result=oneHalf*temp; // oneHalf*operator*(temp)
```



타입 변환에 대해 매개변수가 먹혀들려면 매개변수 리스트에 들어있어야만 한다는 것이다. 즉, 호출되는 멤버 함수를 갖고 있는(this가 가리키는) 객체에 해당하는 암시적 매개변수에는 암시적 변환이 먹히지 않는다



비멤버 함수로 만들어서, 컴파일러 쪽에서 모든 인자에 대해 암시적 타입 변환을 수행하도록 내버려 두는 것이다

```
class Rational{
	...
};

const Rational operator*(const Rational& lhs, const Rational& rhs)
{
	return Rational(lhs.numerator() * rhs.numerator(),
    lhs.denominator() * rhs.denominator());
}

Rational oneFourth(1,4);
Rational result;

result=oneFourth*2;
result=2*oneFourth;
```



### 항목 25 : 예외를 던지지 않는 swap에 대한 지원도 생각해 보자

표준에서 기본적으로 제공하는 swap은 한 번 호출에 복사가 세 번, 일어난다.

```
namespace std{
	template<typename T>
    void swap(T& a,T& b) // std::swap의 전형적인 구현 a의 값과 b의 값을 맞바꾼다.
    {
    	T temp(a);
        a=b;
        b = temp;
    }
}
```



다른 타입의 실제 데이터를 가리키는 포인터가 주성분인 타입은 복사하면 손해다. ex) pimpl 관용구(pointer to implementation)

```

class WidgetImpl{ // Widget의 실제 데이터를 나타내는 클래스
	public:
    ...
private:
	int a,b,c; // 많은 데이터가 있다.
    std::vector<double> v; // 복사 비용이 높다.
    ...
};

class Widget{ // pimpl 관용구를 사용한 클래스
public:
	Widget(const Widget& rhs);
    
    Widget& operator=(const Widget& rhs) // Widget을 복사하기 위해, 자신의 WidgetImpl 객체를 복사한다. 
    {
    	...
        *pImpl=*(rhs.pImpl);
        ...
    }
    ...
private:
	WidgetImpl *pImpl; // Widget의 실제 데이터를 가진 객체에 대한 포인터
};
```

위의 방법에서는 객체 세 개를 복사하고, WidgetImpl 객체 세 개도 복사할 것이다. 

즉, 비효율적이기 때문에 pImpl 포인터만 맞바꾸는 방법으로 해야한다. 그러기 위해서는 std::swap을 Widget에 대해 특수화(specialize)하는 것이다.

```
namespace std{
	template<>
    void swap<Widget>(Widget& a, Widget& b)
    {
    	swap(a.pImpl, b.pImpl); // Widget을 swap하기 위해 각자의 pImpl 포인터만 맞바꾼다.
    }
}
```

이 함수가 std::swap의 완전 템플릿 특수화(total template specialization) 함수라는 것을 컴파일러에게 알려주는 부분이다.

하지만 여기에 pImpl 포인터에 접근하려고 하기 위해서는 포인터가 private 멤버이기 때문에 swap은 public 멤버 함수를 선언하고 그 함수가 실제 맞바꾸기를 수행하도록 만든 후에, std::swap의 특수화 함수에게 그 멤버 함수를 호출하는 일을 맡긴다.

```
class Widget{
public:
	...
    void swap(Widget& other)
    {
    	using std::swap;
        
        swap(pImpl, other.pImpl);
    }
    ...
};

namespace std{
	template<>
    void swap<Widget>(Widget &a, Widget &b)
    {
    	a.swap(b);
    }
}
```

만약 Widget과 WidgetImpl이 클래스가 아니라 클래스 템플릿으로 만들어져 있어서, WidgetImpl에 저장된 데이터의 타입을 매개변수로 바꿀 수 있다면 어떻게 할 수 있을까

아마 아래와 같이 생각할 수 있다.

```
namespace std{
	template<typename T>
    void swap<Widget<T>> (Widget<T> &a, Widget<T>& b)
    {
    	a.swap(b);
    }
}
```

하지만 위 코드는 C++는 클래스 템플릿에 대해서는 부분 특수화(partial specialization)를 허용하지만 함수 템플릿에 대해서는 허용하지 않도록 정해져 있다.



그렇기 때문에 부분적으로 특수화하기 위해서는 오버로드 버전을 추가하면 된다.

```
namespace std{
	template<typename T>
    void swap(Widget<T>& a, Widget<T>& b)
    {
    	a.swap(b);
    }
}
```

std 내의 템플릿에 대한 완전 특수화는 괜찮지만 std에 새로운 템플릿을 추가하는 것은 괜찮지 않다.



템플릿 전용 버전을 사용하기 위해서는 멤버 swap을 호출하는 비멤버 swap을 선언해 놓되, 이 비멤버 함수를 std::swap의 특수화 버전이나 오버로딩 버전으로 선언하지만 않으면 된다.

```
namespace WidgetStuff{
	... // 템플릿으로 만들어진 WidgetImpl 및 기타 등등
    template<typename T> // 이전과 마찬가지로 swap이란 이름의 멤버 함수가 들어있다.
    class Widget{...};
    ...
    
    template<typename T> // 비멤버 swap 함수
    void swap(Widget<T>& a, Widget<T>& b) // 이번엔 std 네임스페이스의 일부가 아니다.
    {
    	a.swap();
    }
}
```

컴파일러는 C++의 이름 탐색 규칙(인지 기반 규칙(argument-dependent lookup) 혹은 쾨니그 탐색(Koening lookup)으로 알려져있다)에 의해 WidgetStuff 네임스페이스 안에서 Widget 특수화 버전을 찾는다.

만약 클래스 타입 전용의 swap을 많은 곳에서 호출되도록 만들고 싶으면 그 클래스와 동일한 네임스페이스 안에 비멤버 버전의 swap을 만들어 놓고, 그와 동시에 std::swap의 특수화 버전도 준비해두어야 한다.



```
template<typename T>
void doSomething(T& obj1, T& obj2)
{
	...
    swap(obj1, obj2);
    ...
}
```

이 swap을 호출할 가능성은 3가지가 있다

1. std에 있는 일반형 버전

2. std의 일반형을 특수화한 버전 : 있을 수도, 없을 수도 있다

3. T타입 전용의 버전 : 있거나 없거나 할 수 있으며, 어떤 네임스페이스 안에 있거나 없거나 할 수도 있다. (std 안에는 없어야 한다)
   
   

예시

```
template<typename T>
void doSomething(T& obj1, T& obj2)
{
	using std::swap; // std::swap을 이 함수 안으로 끌어올 수 있도록 만드는 문장
    ...
    swap(obj1,obj2); // T 타입 전용의 swap을 호출한다.
    ...
}
```

이는 T 전용 버전이 있으면 그것이 호출되도록 하고, T타입 전용 버전이 없으면 std의 일반형 버전이 호출되록 만든다

컴파일러가 위의 swap 호출문을 만났을 때 하는 일은 현재의 상황에 딱 맞는 swap을 찾는 ㅓㄳ이다.



T전용 swap이 없으면 컴파일러는 그 다음 순서를 밟는데, 이 함수가 std::swap을 볼 수 있게 해 주는 using 선언(using declaration)이 함수 앞부분에 떡 하니 있기 때문에 std의 swap을 쓰게끔 결정할 수도 있다



조심해야 할점은 한정자가 붙게 되면 C++가 호출될 함수를 결정하는 메커니즘에 영향을 준다.



정리

1. 표준에서 제공하는 swap이 클래스 및 클래스 템플릿에 대해 납득할 만한 효율을 보이면, 아무것도 하지 말기

2. 표준 swap의 효율이 충분하지 않다면 다음과 같이 한다

2-1. public 멤버 함수로 두기

2-2. 클래스 혹은 템플릿이 들어 있는 네임스페이스와 같은 네임스페이스에 비멤버 swap을 만들어 놓는다.그리고 1번에서 만든 swap 멤버 함수를 이 비멤버 함수가 호출하도록 만든다,.

2-3. 새로운 클래스를 만들고 있다면, 그 클래스에 대한 std::swap의 특수화 버전을 준비해둔다. 이 특수화 버전에서도 swap멤버 함수를 호출하도록 만든다.

3. 사용자 입장에서 swap을 호출할 때, swap을 호출하는 함수가 std::swap을 볼 수 있도록 using 선언을 반드시 포함시킵니다. 그 다음에 swap을 호출하되, 네임스페이스 한정자를 붙이지 않도록 한다.
   
   

swap을 쓸모 있게 만들기 위해서는 예외를 만들면 안된다. 강력한 예외 안전성 보장(strong exception-safety guarantee)을 제공하도록 도움을 주는 방법이 있다.(항목29에 있다)

근데 이 버전은 멤버 버전 swap이 예외를 던지지 않아야 한다는 가정을 깔고 있다.



#### 나의 생각

멤버 함수와 비멤버 함수의 차이가 클래스의 유무 정도로만 생각하였는데 연산자와 swap 등에서도 영향을 많이 끼친다는 사실을 알게 되었다. 사소한 차이에도 컴파일 에러도 영향을 끼칠 수 있는 사실을 생각해두어야겠다.
